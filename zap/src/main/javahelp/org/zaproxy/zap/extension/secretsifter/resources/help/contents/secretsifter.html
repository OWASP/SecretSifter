OWASP SecretSifter

OWASP SecretSifter is a passive scan rule that detects secrets, credentials, API tokens and personally identifiable information (PII) exposed in the content a web application actually delivers to the browser: response bodies, JavaScript bundles, server-rendered state blobs (Next.js / Nuxt / Redux), JSON and XML responses, and request headers.

How it works

The rule runs automatically as part of ZAP's passive scanning on every message in scope. It inspects each HTTP response (and request header blob) with the unified SecretSifter detection engine — 158 format-anchored vendor token patterns (AWS, GCP, Azure, Stripe, GitHub, Slack, Twilio, SendGrid, and more), 279 context rules, plus generic key/value, connection-string, JWT, high-entropy and PII detectors. False positives are suppressed with placeholder detection, entropy gating and allowlists.

Scanning is entirely local to ZAP. The add-on makes no outgoing network connections of its own.

Using it

  1. Proxy your target application through ZAP, or import traffic / spider the site.
  2. Each exposed secret is reported as an alert named Exposed Secret: <type>, with the matched evidence, the source URL, and a risk level based on the secret type.
  3. Review alerts under the Alerts tab and triage as usual.

Alert risk levels

High-impact vendor tokens (for example cloud provider keys, Stripe live keys, GitHub tokens) are reported at High risk; context and generic key/value findings are reported at Medium or Low depending on the key name and value entropy.
